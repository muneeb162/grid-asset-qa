# DEF-001: Duplicate check accepts the same name spelled with ß and SS

| Field | Value |
|---|---|
| Status | Fixed, regression test in place |
| Severity | Medium |
| Priority | P1 |
| Component | API, asset creation (`app/service.py`) |
| Business rule | BR-01: asset names are unique, ignoring case |
| Found by | Test case TC-028 (error guessing: German spelling rules) |
| Regression test | `tests/api/test_assets_api.py::test_duplicate_check_follows_german_spelling` |

## Summary

An asset named "Trafo Kreuzstraße" and a second asset named "TRAFO KREUZSTRASSE" can both be created. In German, ß is written as SS in capitals, so these are the same name and the second request should be rejected.

## Steps to reproduce

1. `POST /api/assets` with `"name": "Trafo Kreuzstraße"` and otherwise valid data
2. `POST /api/assets` with `"name": "TRAFO KREUZSTRASSE"` and otherwise valid data

## Expected result

Step 2 returns `409 Conflict` with "already exists".

## Actual result

Step 2 returns `201 Created`. The register now holds two entries for one physical asset.

## Impact

Operators searching for a substation can find one record and report an outage against it while the duplicate still shows the asset as in service. In a grid register, a duplicate is a data quality problem with operational consequences.

## Root cause

The comparison used `str.lower()`. Python lowercases "SS" to "ss" but keeps "ß" as "ß", so the two strings never match. Umlauts were not affected, because "Ö".lower() is "ö".

## Fix

Compare with `str.casefold()`, which is designed for caseless matching and maps "ß" to "ss".

## Verification

- TC-028 fails before the fix (2 of 3 cases) and passes after it
- Full suite passes; coverage unchanged
